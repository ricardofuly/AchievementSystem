Achievement System

Achievements orientados a dados, com rewards entregues pelo host e sincronização com a Steam, feitos para jogos multiplayer P2P (listen server).

Visão geral

O plugin separa três responsabilidades:

  • O designer cria achievements como Data Assets, sem código.
  • O gameplay só avisa que algo aconteceu, com uma linha: ReportAchievementEvent.
  • O plugin cuida de progresso, desbloqueio, rewards, replicação, save e Steam.
MóduloTipoResponsabilidade
AchievementsCoreRuntimeDefinições, componente, subsystem, rewards, save e interfaces. Não depende da Steam.
AchievementsSteamRuntime (Win64, Linux, Mac)Implementação da plataforma Steam.
AchievementsUIRuntimeClasses base de widgets: toast, lista e entrada.
AchievementsEditorEditorMenu Tools → Achievements: validação, exportação e esta documentação.

Instalação

  1. Copie a pasta Plugins/AchievementSystem para o seu projeto e ative o plugin. Feche o editor e compile pela IDE.
  2. Em Project Settings → Asset Manager → Primary Asset Types to Scan, adicione uma entrada:
    • Primary Asset Type: AchievementDefinition (exatamente este nome);
    • Asset Base Class: AchievementDefinition;
    • Directories: a pasta onde ficarão as definições, por exemplo /Game/Achievements.
    Reinicie o editor depois de mudar essa configuração.
  3. Adicione o componente AchievementComponent ao seu PlayerState.
  4. Crie as gameplay tags: Achievement.* para os achievements e Event.* para os eventos.
  5. Se o achievement tiver rewards, ligue cada tipo de reward a um granter em Default Granters.
Teste rápido Crie uma definição, rode o PIE com 2 jogadores em Play As Listen Server e digite Achievements.SelfTest no console da janela do host.

Como funciona

A regra principal: o host decide o progresso e entrega os rewards; cada jogador conversa com a própria Steam. A Steam só aceita achievements da conta logada na máquina, então o host nunca escreve na Steam de outro jogador.

Host (listen server)

  • Recebe os eventos do gameplay
  • Avalia condições e pré-requisitos
  • Atualiza o progresso e desbloqueia
  • Entrega os rewards pelos granters

Cada jogador (inclusive o host)

  • Guarda o próprio save local
  • Envia o save ao host ao entrar
  • Recebe o progresso replicado
  • Sincroniza com a própria conta Steam

Ciclo de vida

  1. Ao entrar na partida, o jogador carrega o save local e envia um snapshot ao host. O host valida o tamanho, descarta ids desconhecidos e limita os valores à meta.
  2. O gameplay no host chama ReportAchievementEvent. Todo achievement que ouve aquele evento avança.
  3. Quando o valor atinge a meta, o achievement é desbloqueado e, com bAutoClaimRewards, os rewards são entregues.
  4. O progresso é replicado só para o dono do PlayerState (FastArray, só as mudanças).
  5. O dono salva localmente e põe a operação na fila da Steam. A fila é persistida e tentada de novo até a Steam confirmar.

Garantias

  • Progresso nunca regride: o save local e o estado no host só aumentam. Se o host ainda não recebeu o save do jogador, valores menores replicados não sobrescrevem o save, e o que já contou no host antes do save chegar é somado, não perdido.
  • Save com backup: a cada início, uma cópia do save que carregou sem erro vai para <Slot>_Backup. Se o save principal sumir ou corromper, o backup é restaurado.
  • Reward nunca duplicado: cada reward tem um bit de "entregue". Novas tentativas só processam o que falta.
  • Nada se perde offline: as operações pendentes da Steam ficam no save e são enviadas quando ela voltar.
  • Reinstalação: ao iniciar, o plugin compara o save com a Steam. O que está desbloqueado na Steam é recuperado no save, e rewards pendentes são entregues ao entrar na próxima partida.

Split-screen

Cada jogador local tem o próprio PlayerState, componente, save e UI:

  • Jogador principal (o primeiro local player, logado na Steam): save em Achievements e sincronização com a Steam.
  • Demais jogadores (convidados): saves próprios em Achievements_P1, Achievements_P2... Eles ganham achievements e rewards no jogo, mas não na Steam, porque ela só aceita a conta logada.
  • Os widgets do plugin usam o jogador dono de cada widget, então cada metade da tela mostra os próprios avisos e a própria lista.
  • O save do convidado fica ligado à posição do jogador local (P1, P2...). Se os jogadores trocarem de posição, trocam de save.
Limitação do modelo P2P Sem um servidor próprio, cada jogador é dono do próprio save. O host valida limites, mas um jogador pode editar o arquivo de save. Para rewards valiosos, considere um backend próprio.

Criando achievements

No Content Browser: botão direito → Miscellaneous → Data Asset → AchievementDefinition, dentro da pasta configurada no Asset Manager.

CampoPara que serve
IdTag única do achievement, por exemplo Achievement.Combat.Kill100.
PlatformApiNameNome do achievement cadastrado no Steamworks, por exemplo ACH_KILL_100. Vazio = achievement só interno, sem Steam.
PlatformStatNameOpcional. Stat da Steam que espelha o progresso e mostra o aviso nativo de progresso da Steam.
DisplayName, Description, IconExibidos pela UI. O ícone é carregado de forma assíncrona.
bHiddenMascara nome, descrição e ícone na lista até o desbloqueio.
ListenedEventsEventos que fazem este achievement avançar.
TargetValue1 = desbloqueia de uma vez. Maior que 1 = incremental (ex.: 100 kills).
PrerequisitesAchievements que precisam estar desbloqueados antes de este começar a contar.
ConditionsFiltros avaliados a cada evento. Veja Condições.
RewardsO que o jogador ganha, até 32 por achievement. Veja Rewards.

A validação roda ao salvar o asset e acusa: Id vazio ou repetido, API name repetido, nenhum evento ouvido, reward vazio e pré-requisito apontando para o próprio achievement.

Reportando eventos

O plugin funciona por eventos: o gameplay não diz "desbloqueie X", e sim "aconteceu Y". Um evento pode alimentar vários achievements, e o designer cria achievements novos sem tocar em código.

Sempre no host Reporte eventos só no host (GameMode, lógica de dano, objetivos). Chamadas feitas no cliente são ignoradas.

Blueprint

Report Achievement Event
  Player:       (PlayerState de quem fez a ação)
  Event Tag:    Event.Enemy.Killed
  Amount:       1
  Context Tags: (opcional) Difficulty.Hard, Weapon.Sword

Para todos os jogadores da partida (ex.: "time venceu"), use Report Achievement Event For All.

C++

#include "AchievementStatics.h"

FGameplayTagContainer ContextTags;
ContextTags.AddTag(TAG_Difficulty_Hard);

UAchievementStatics::ReportAchievementEvent(KillerPlayerState, TAG_Event_Enemy_Killed, 1, ContextTags);

Condições

Uma condição decide se um evento conta para o achievement. Ela roda no host, a cada evento.

Prontas

ClasseO que faz
Requires Context TagsSó conta se o evento trouxer todas as tags em RequiredTags.

Criando em Blueprint

  1. Blueprint Class → All Classes → AchievementCondition, por exemplo BP_Cond_PlayerAlive.
  2. Em My Blueprint → Functions → Override, escolha Is Satisfied.
  3. Use o Context (EventTag, Amount, ContextTags, Player) e retorne true para contar ou false para ignorar.
  4. Variáveis marcadas como Instance Editable viram parâmetros editáveis dentro do Data Asset.
  5. Na definição, clique no + em Conditions e escolha a classe.

Criando em C++

UCLASS(meta = (DisplayName = "Player Alive"))
class UMyCondition_PlayerAlive : public UAchievementCondition
{
	GENERATED_BODY()

protected:
	virtual bool IsSatisfied_Implementation(const FAchievementEventContext& Context) const override
	{
		const APawn* Pawn = Context.Player ? Context.Player->GetPawn() : nullptr;
		return Pawn != nullptr;
	}
};
Cuidados
  • Sem estado: a mesma instância é usada por todos os jogadores, então não guarde contadores nela. Contagem é papel do TargetValue.
  • Sem World direto: a condição vive dentro do Data Asset. Chegue no mundo a partir de Context.Player.
  • Dados que só quem dispara o evento conhece devem ir como ContextTags.

Rewards e granters

Um reward tem duas partes, separadas para o plugin não depender do inventário do seu jogo:

  • Reward: só dados, descreve o que dar (ex.: 100 de ouro).
  • Granter: a lógica que entrega de fato, no seu inventário ou carteira.

Prontos

RewardCampos
Item RewardItemId (Primary Asset Id), Quantity
Currency RewardCurrencyTag, Amount

Todo reward tem também DisplayName e Icon, exibidos pela entrada da lista.

Exemplo completo: AchievementExampleWalletComponent, uma carteira replicada para colocar no PlayerState, e AchievementExampleCurrencyGranter, que deposita o Currency Reward nela.

Criando um reward em Blueprint

  1. Blueprint Class → All Classes → AchievementReward, por exemplo BP_Reward_Skin.
  2. Crie as variáveis (ex.: SkinId) e marque como Instance Editable. Não coloque lógica aqui.

Criando um granter em Blueprint

  1. Blueprint Class → Object, por exemplo BP_Granter_Skin.
  2. Em Class Settings → Implemented Interfaces → Add, escolha AchievementRewardGranter.
  3. Em My Blueprint → Interfaces, implemente Grant Reward: faça Cast do Reward para a sua classe, entregue usando o Player e retorne o resultado.
  4. Em Project Settings → Plugins → Achievements → Default Granters, clique no + e ligue BP_Reward_Skin → BP_Granter_Skin.

Um granter registrado para uma classe base também atende as classes filhas.

Resultados do granter

ResultadoQuando usarO que acontece
GrantedEntregouMarcado como entregue e nunca repetido.
DeferredBloqueio temporário (ex.: inventário cheio)Fica pendente. É entregue quando o jogo chamar RetryPendingRewards() no host, por um claim manual ou na próxima partida.
FailedErro (ex.: componente faltando)Fica pendente e gera erro no log. RetryPendingRewards() pula; só um claim manual ou a próxima partida tenta de novo.

Auto-claim ou claim manual

  • bAutoClaimRewards = true (padrão): os rewards são entregues no desbloqueio.
  • bAutoClaimRewards = false: o jogador resgata pela UI, com o botão Claim da entrada ou ClaimAll da lista.

Repetindo rewards Deferred

// No host, quando o bloqueio sumir (ex.: inventário liberou espaço)
UAchievementStatics::GetAchievementComponent(PlayerState)->RetryPendingRewards();
O granter roda só no host O que ele alterar precisa ser replicado pelo seu sistema para o cliente ver. Assim como a condição, um único granter atende todos os jogadores: não guarde estado nele.

Interface (UI)

As classes base ficam no módulo AchievementsUI. O C++ fornece dados e eventos, e o visual fica no seu Widget Blueprint. Os widgets encontram sozinhos o componente do jogador local e tentam de novo até o PlayerState replicar.

Toast (aviso de desbloqueio)

  1. Crie um Widget Blueprint com parent AchievementToastWidget.
  2. Implemente ShowToast(Toast): preencha os textos com Toast.Definition, diferencie Toast.Type (Unlocked ou RewardsClaimed) e toque a animação de entrada.
  3. Implemente OnQueueEmpty para esconder o widget.
  4. Adicione o widget à tela no HUD ou no PlayerController.
PropriedadePadrãoEfeito
AutoFinishSeconds4Fecha cada aviso após N segundos. Com 0, o Blueprint chama FinishToast, por exemplo ao fim da animação.
bShowRewardToaststrueTambém mostra um aviso quando os rewards são entregues.

Lista de achievements

  1. Entrada: Widget Blueprint com parent AchievementEntryWidget.
    • Implemente OnDataChanged(Data) com os textos, uma ProgressBar ligada a Data.Progress e a visibilidade do botão por Data.bClaimable.
    • Implemente OnIconLoaded(Icon).
    • Rewards: Data.Rewards traz nome, ícone e bGranted de cada reward. Use Data.bHasRewards para mostrar ou esconder a área de rewards, e implemente OnRewardIconLoaded(RewardIndex, Icon), que dispara uma vez por reward quando o ícone termina de carregar.
    • Ligue o botão de resgatar a Claim.
  2. Lista: Widget Blueprint com parent AchievementListWidget.
    • Adicione um painel (Scroll Box, Vertical Box...) chamado EntryContainer.
    • Em EntryClass, escolha o Blueprint de entrada.
    • Opcional: implemente OnListUpdated e use GetUnlockedCount / GetTotalCount para mostrar "3 / 20".

Ordem da lista: resgatáveis, desbloqueados, em progresso e bloqueados. Achievements ocultos aparecem mascarados até o desbloqueio; para escondê-los totalmente, desligue bShowHiddenLocked.

Steam

  1. Cadastre os achievements no site de parceiros do Steamworks, em Stats & Achievements. Use a planilha exportada como referência.
  2. Preencha o PlatformApiName de cada definição com o mesmo nome cadastrado.
  3. Configure o OnlineSubsystemSteam do projeto (AppID e DefaultEngine.ini), como em qualquer jogo Steam na Unreal.
  • Os desbloqueios são enviados na hora. Stats e outras operações pendentes são agrupados e enviados a cada CommitIntervalSeconds.
  • Sem a Steam, por exemplo no editor sem o cliente aberto, o plugin usa a plataforma Null e tudo funciona localmente.
  • Para outra plataforma (Epic, consoles), implemente IAchievementPlatform e registre um IAchievementPlatformFactory como modular feature, como faz o módulo AchievementsSteam.
No PIE, todos os jogadores usam a mesma conta Steam Um achievement desbloqueado por um jogador volta para os outros pela reconciliação. Use Achievements.Reset em cada janela para começar do zero.

Testes automatizados

O módulo AchievementsTests, só de editor, traz Automation Specs no grupo AchievementSystem:

GrupoO que valida
AchievementSystem.MergeO progresso nunca regride: valores máximos, data de desbloqueio mais antiga, união dos rewards entregues e limite pela meta.
AchievementSystem.StorageSalvar e carregar, backup, recuperação de save corrompido ou apagado, e a plataforma Null.
AchievementSystem.ProgressEventos, metas, eventos ignorados, vários achievements por evento, jogadores independentes, pré-requisitos e condições.
AchievementSystem.RewardsAuto-claim e claim manual, Deferred e Failed, RetryPendingRewards, ClaimAll e a garantia de nunca entregar duas vezes.

Rodando no editor

Em Tools → Test Automation, filtre por AchievementSystem, marque os testes e clique em Start Tests.

Isolados do projeto Os testes criam as próprias definições, tags (AchievementTests.*), granter e saves temporários. Não dependem dos assets do projeto e não alteram os saves reais.

Solução de problemas

SintomaCausa e solução
Loaded 0 achievement definitions O Primary Asset Type no Asset Manager precisa ser exatamente AchievementDefinition, e o diretório deve apontar para a pasta das definições. Reinicie o editor depois de mudar.
Achievement já aparece desbloqueado num teste novo Com a Steam ativa, os jogadores do PIE compartilham a conta, e a reconciliação traz o desbloqueio. Rode Achievements.Reset em cada janela e reinicie o PIE.
No granter registered for reward class ... Falta ligar a classe do reward a um granter em Default Granters.
Invalid default granter ... A classe do granter não implementa a interface AchievementRewardGranter.
Reward não é entregue e o achievement fica resgatável O granter retornou Deferred ou Failed. Veja o log e use RetryPendingRewards() ou um claim manual.
ReportAchievementEvent: ... has no UAchievementComponent O componente não foi adicionado ao PlayerState.
Toast ou lista não aparece no cliente Confira se o widget foi adicionado à tela do jogador local e se o evento foi reportado no host. Use Achievements.Dump na janela do cliente.
Módulo novo ou mudança de reflexão não aparece O Live Coding não carrega módulos novos nem aplica todas as mudanças de UCLASS/UINTERFACE. Feche o editor e compile pela IDE.
Steam rejected achievement '...' O PlatformApiName não bate com o cadastrado no Steamworks, ou as mudanças no site não foram publicadas.
